# 화면·연출 명세 (UI-SPEC v3)

태블릿과 PC는 `100dvh` 격자 안에서 실제 글자 크기로 배치한다. 화면 전체를 transform scale로 축소하지 않는다.
768px 미만은 문서 흐름으로 바꾸고 세로 스크롤을 허용한다. 모든 기기에서 본문과 버튼은 14px 이상, 보조 표기는 12px 이상, 터치 대상은 44×44px 이상이다.
한국어는 `keep-all`과 `overflow-wrap: anywhere`, 제목은 `balance`, 설명은 `pretty`로 배치한다.

화면별 배치 원칙:

- 교배: 주문 패널 옆에 부모 4개체씩, 증축 시 쪽 넘김. 부모 선택과 예측, 교배 단추를 함께 둔다. 반복 해설은 기존 [교배 도움]에서 다시 읽는다.
- 출하: PC와 가로 태블릿은 손패 8장 한 줄, 세로 태블릿은 4×2. 예측과 납품은 위, 행동과 자손 덱은 아래에 둔다. 세로 태블릿 주문 패널은 위쪽 띠로 바뀐다.
- 정산: 작은 영수증 한 장에 보상 내역과 받기 단추를 둔다.
- 선발: 후보 4개체씩 쪽을 넘기며 비교한다. 온실 교체 대상도 4개체씩 표시하고 공개 유전자형을 유지한다. 쪽을 바꿔도 선택은 유지한다.
- 상점: 상품 5개를 한 화면 격자로 배치한다. 이름을 누르면 효과 설명 영수증을 연다. 다음 주문 서류와 다음 주문, 새로고침 단추는 항상 같은 자리다.
- 홈: 새 연대기와 저장 목록을 나란히, 저장 목록은 연대기별 쪽 넘김으로 표시한다. 준비 단계의 첫 카드 격자는 B에서 조정할 수 있게 독립된 `.wiz__styles`로 남긴다.
- 이야기: 전체 화면 장면 위에 작은 사진과 이름 꼬리표, 아래쪽 자막을 놓는다. 대화 기록, 노트와 편지는 내용 단위 쪽 넘김을 사용한다. 선생님 안내와 개인정보만 본문 스크롤을 허용한다.
- 인물 서류는 `src/ui/dossier.ts`, 납품 형질은 `src/ui/traitBadge.ts`를 공유한다. 설명 그림은 B에서 `EXPLAIN_ASSET_ROOT`(`explain/`)와 manifest 파일명으로 연결한다.

기준 화면 실측은 총괄에게 인계한다. 이 세션에서는 서버와 Chromium 실행 권한이 없어 스크롤 제거와 줄바꿈을 실측하지 않았다. `_workspace/redesign-2026-10-23/ui-a/shoot.cjs`와 `QA.md`가 측정 절차다. 아래 이전 명세와 충돌하면 이 절의 배치 원칙이 우선한다.

## 1. 화면 목록
1. **타이틀** — 과수원 소개와 [새 연대기 시작]을 왼쪽에, ‘내 연대기’ 저장 목록을 오른쪽에 표시한다. [플레이 방법] [연구 노트] [설정] [선생님 안내]를 제공한다.

   새 연대기는 진행 방식 → 플레이 범위 → 운영 팀 → 과수원 이름의 네 단계로 준비한다. 플레이 범위는 카드를 선택한 뒤 [다음]으로 넘어가며, 뒤로 가도 선택을 유지한다.
   범위는 전체 8시즌·24계약 / 짧은 4시즌·12계약과 단원 게임 2시즌·6계약으로 구분한다. 성염색체는 시즌 3~4, 염색체 수는 5~6, 유전자 편집은 7~8이다. 시즌 1~8 표시에서 선택한 구간을 강조한다.
   진행 방식은 [재도전 허용]과 [실패 시 종료]다. 실패 후의 진행을 설명하고 두 방식 모두 중간 저장이 가능함을 알린다.
   운영 팀은 교배·선발팀, 유전자 편집팀, 형질전환팀이다. 모든 팀의 기본 교배·선발은 같으며 추가 도구·시작 비법·보상·제한을 설명한다. 유전자 편집 단원에서는 해당 팀을 자동으로 지정한다.
   이름은 선택 사항이며 최대 12자다. 진행 방식·범위·팀·예상 시간을 확인하고 [플레이 시작]을 누른다. 예상 시간은 선택과 읽기 속도를 고려한 안내치다.
   저장 카드에는 이름, 상태, 모드, 팀, 전체 예상 시간, 현재 시즌·계약, 완료 계약 수와 마지막 저장 시각을 표시한다. 진행 상태에 따라 [이어하기] [재도전 준비] [기록 보기]를 제공하며 삭제 버튼은 분리한다. 새 연대기를 시작해도 기존 기록은 보존한다. 기록은 이 기기 브라우저에 저장한다.

11. **연구 노트** — 왼쪽에 단원별 목차, 오른쪽에 작은 종이 본문을 배치한다. 목차는 단원별, 본문은 내용별 쪽 넘김이며 제목을 자르지 않는다.
    휴대폰에서는 목차를 본문 위에 놓는다. 개념을 고르면 모달 본문을 해당 기록의 첫 줄로 스크롤한다. 모달의 닫기 버튼은 화면 안에 유지한다.
    본문은 발견한 현상 → 실제 과학 설명 → 게임에서 정한 규칙 → 성취기준 → 해당 연대기에서 관찰한 결과 순서다. 부모 유전자형·씨앗 분포·납품 수량을 실제 계약 기록에서 가져온다.
    미발견 개념은 잠겨 있으며 [단원별] [성취기준별]로 목차를 바꿀 수 있다.
12. **끝 (gameover/victory)** — "플레이 기록": 도달 시즌, 계약 완료 수, 재도전 수, 최고 출하 점수, 족보별 횟수, 발견 수,
    **정체 공개**: 온실 모든 포기의 실제 유전자형 + 핵형 + 계보(카드가 뒤집히며 공개),
    철학 성찰 한 줄 질문(03-05): "우리 브랜드는 무엇을 택했고 그 대가는 무엇이었나요?"(입력칸, localStorage 만),
    계약별 부모·예측·관찰·납품·재시도 비교 보고서와 텍스트 저장, [새 연대기] [홈으로]. 완료 기록도 저장 목록에서 다시 연다.
    **계약 검토(review)**는 재도전 허용의 실패 화면이다. 조건별 미달 수량과 점수·힌트를 보고 [이 계약 다시 준비]로 계약 시작 상태를 복구한다.
13. **설정** — 음량(전체·음악·효과), 음소거, 연출 속도, 동작 줄이기, 저장 지우기.
14. **선생님 안내** — 이 게임의 개념 ↔ 성취기준 표(GDD 5절), 재도전 허용 설명, "학생 개인정보를 수집하지 않아요(모든 기록은 이 기기 브라우저에만)".
15. **첫 계약 실습** — 짧은 연대기·교배·선발팀·재도전 허용의 첫 계약을 실제 규칙으로 진행한다. 예상 시간은 약 5~8분이다.
    레아 HUD는 주문 확인 → 부모 선택 → 예측 → 교배 → 관찰 → 카드 선택 → 출하 → 보상 → 선발 → 공방의 실제 상태를 읽어 안내한다.
    조작 위치에 테두리를 표시하고 [조작 위치 보기]로 이동한다. 작은 화면에서는 HUD를 접고 이동하며, 접은 안내는 스크롤 중에도 위에 남는다.
    실습은 별도 연대기에 저장하고 확인 단계도 함께 저장한다. 종료할 때 [이 과수원에서 계속하기] 또는 [모드 골라 새로 시작]을 고른다. 보상과 모종은 원래 실습 연대기에 보존한다.

## 2. 조작
키보드: 1–8 카드 선택 토글, Enter 출하, D 솎아내기, S 정렬 전환, Esc 모달 닫기, Space 점수 연출 빨리 감기.
마우스/터치: 탭으로 선택, 비법은 끌어서 순서 변경(터치 길게 눌러 끌기).
툴팁: 카드·비법·시약·보스에 마우스를 올리면(터치는 길게) 설명. 카드 툴팁엔 표현형 문장("루비 과육 · 별무늬 · 당도 15°Bx"),
공개됐으면 유전자형, 멘델의 안경이 있으면 inferableLoci 로 확실한 자리만.

## 3. 느낌 (Balatro 에서 배울 것)
- 모든 것이 살짝 움직인다(부유, 흔들림, 숫자 굴러감). 하지만 prefers-reduced-motion / 설정에서 끄면 즉시 멈춘다.
- 버튼은 누르면 눌리는 감(translateY 2px + 그림자 줄어듦). 호버 소리 아주 작게.
- 숫자 표기는 천 단위 쉼표, 큰 수는 '1.2만'.
- 전환은 0.25~0.4s ease-out, 카드 이동은 FLIP(uid 기준으로 이전 위치→새 위치).

## 4. 검증용 손잡이 (필수)
`?debug=1` 이면 `window.__sa = { game, fast(on), autoplay(steps) }` — fast 는 모든 연출 시간을 0 으로. autoplay 는 봇처럼 교배·최선 출하·공방 나가기를 반복.
시드·연대기 길이·진행 방식 선택, [검증 시작] [자동 진행] [빠른 연출]을 화면에 제공한다. 도구가 차지하는 높이를 제외하고 게임 화면을 맞춘다.
QA 가 백그라운드 탭(초당 몇 프레임)에서도 게임을 끝까지 진행해 볼 수 있어야 한다. 연출은 requestAnimationFrame 대신
Web Animations API + setTimeout 기반으로 끝이 보장되게(애니메이션이 멈춰도 게임 진행이 막히지 않게 `finished` 에 타임아웃 병행).

### 총괄 A1 검수 후 보완

출하와 선발의 카드 높이는 남는 세로 영역을 사용한다. 가로 화면 출하 카드는 최대 44dvh, 선발 후보는 최대 40dvh 안에서 컨테이너 높이를 따른다. 세로 태블릿은 손패 4×2가 남은 칸을 채운다. 실제 높이는 보고서의 카드 높이/화면 높이 비율로 확인한다.

상점은 그림, 이름, 효과, 가격 단추를 한 묶음으로 표시하고 원문 효과는 생략하지 않는다. 동시에 발생한 안내는 한 개씩 큐에서 꺼내 아래쪽 고정 띠에 표시한다. 도구 줄과 단추는 최소 48px을 확보한다. 노트 창과 목차는 어두운 유리이며 오른쪽 기록 쪽만 작은 종이 물건이다. 첫 준비 단계의 선택 상자는 내용 높이만 차지한다.

서막과 시즌 장면의 입자 장식은 화면 밖으로 확장하지 않는다. 해설처럼 초상이 없는 경우에도 자막은 화면 폭의 86%를 쓰며, 말하는 사람과 사진 아래에 18~22px 자막을 놓는다. 화면 아래 단추와 대화 기록은 같은 전체 화면 안에 남는다.

총괄 A1 실측에서 PC·태블릿 8개 크기의 title/wizard/notes/play/cashout/select/shop 문서 스크롤과 12px 미만 글자는 0이었다. 위 후속 보완의 실제 화면은 총괄이 다시 측정한다.
