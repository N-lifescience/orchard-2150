## 장점과 남은 한계

장점은 원하는 유전 형질을 만들고 선발하는 행동이 승리 조건과 직접 연결된다는 점이다. 실패 뒤 관찰을 보존하고 같은 조건에서 선택을 바꿀 수 있으며, 단원 게임으로 수업 범위를 좁힐 수 있다.

전체 연대기는 한 차시에 모두 끝내는 구성으로 권하지 않는다. 단원 또는 빠른 연대기에 수업 시간을 배정하고 돌아보기 8~10분을 남긴다. 표시한 시간은 배정안이며 학생 대상 측정값이 아니다.

카드 점수 규칙에 익숙해지는 시간과 유전 내용을 추론하는 시간이 함께 필요하다. 교사는 첫 교배를 함께 해 보고, 학생이 사용한 부모의 공개 정보와 실제 자손 수를 근거로 설명하도록 도와야 한다. 선택을 시행착오로만 반복해도 일부 계약을 해결할 수 있으므로 성공 자체를 개념 이해의 증거로 삼지 않는다.

다음 교육적 검증은 학생 시범 수업에서 풀이 시간·잘못된 일반화·재도전 때 바꾼 선택을 관찰하고, 게임 밖의 새로운 교배 문제와 사후 토론으로 전이를 확인하는 것이다. 학생 대상 검증은 이번 코드 수정의 결과에 포함되지 않는다.


## 2026-10-26 — 점수 부담, 예측, 이형접합 표지, 단원 연습 보완

판단 기준은 루트 `학습게임_설계이론.html` 8절의 “내용이 복잡할수록 조작은 단순해야 한다”와 위 검토의 내재적 통합, 형평성, 피드백 항목이다. 이 문서는 코드와 자동 플레이를 검토한 기록이며 학생 대상 학습 효과 검증은 아니다.

### 선택한 방법과 이유

1. **수업 완료와 점수 보상을 분리했다.** 수업 모드는 필수 형질 수량을 채우면 완료한다. 단원 연습은 아래의 부모 조합 조건도 충족해야 한다. 점수 원값을 보전하거나 부풀리지 않고 실제 족보 점수를 기록한다. 기존 점수 목표를 달성하면 정산에서 $2를 더 받는다. 족보, 비법, 출하 보상과 형질 납품에 따른 연구 레벨 상승은 유지했다. 유전 과제를 해결한 뒤 카드 최적화 때문에 진행이 막히는 일을 없애려는 선택이다. 형질 목표가 없는 특수/옛 계약은 기존 점수 조건을 유지한다. 도전 모드(master)의 목표 점수와 점수 충족 의무는 그대로다.
2. **예측을 엔진에서 요구하고 판정한다.** 공개된 정상 2배체 부모의 R 자리로 기대 확률을 정확히 계산한다. 루비 확률이 더 큼, 골드 확률이 더 큼, 같은 확률(정확히 1:1)을 고른다. 정답 여부는 실제 52개체의 우연한 비율과 무관하다. 관찰 화면에 판정, 기대 확률과 실제 개체 수를 보여 준다. 정답이면 해당 계약의 솎아내기 +1, 오답은 무벌점이다. 붓으로 다시 교배해도 한 시도에 보상은 한 번만 받으며, 재도전에서는 계약 시작 상태로 돌아가므로 누적되지 않는다. 기대 확률, 판정과 보상 여부는 `PredictionRecord`를 통해 `OrderRecord`와 텍스트 보고서에 남긴다. 비공개 부모, 다른 종, 배수체/이수성, 염기 서열 편집, 비분리 조건(시즌 5 이후 또는 냉해)은 단순 과육색 예측을 생략한다. 도전 모드의 예측은 선택이며 자원 보상은 없다.
3. **퍼넷 노트의 공개 시점을 일관되게 늦췄다.** 수업 모드는 예측 선택 직후에도 비율을 공개하지 않는다. 실제 교배를 실행한 뒤 과육색 판정을 보고, 비법의 빛깔/당도 모의 기대 분포는 [자손 덱]에서 펼쳐 볼 수 있다. 생각 도우미는 학생이 배우자 조각과 조합 칸을 직접 채우는 방식을 유지한다. 비공개 부모의 기대 분포는 API에서도 반환하지 않는다. 도전 모드의 교배 전 퍼넷 노트는 유지했다.
4. **`heterosis`를 ‘이형접합 표지’로 바꿨다.** 저장 id, 가격과 배수 +2 효과는 유지했다. 실제 적용 자리 R, S, L을 설명에 적고 생장이나 수확량의 우월성을 뜻하지 않는 게임 보상으로 명시했다. 아이콘은 서로 다른 R/r 표지로, 갤러리는 같은 이름과 효과로 맞췄다. `heterozygote` 개념 카드의 검정교배 설명은 유지하고 한 자리의 이형접합으로 생장/수확량을 판단할 수 없다고 적었다.
5. **단원 연습은 부모 조합의 기대 분포도 필수 조건으로 삼았다.** 출하에서 우연히 목표 몇 개체를 찾는 방식만으로는 통과하지 못한다. `unit-sex`는 딸/아들의 잎색을 각각 모두 은빛/초록으로 만드는 조합을 구분한다. 시작 암그루는 LL과 ll이고, 두 종류의 수그루와 비교용 루미를 확정 제공한다. `unit-chromo`는 2n/3n/4n과 모든 자손의 과육색을 함께 맞추며, 순수 루비/골드 4배체와 2배체를 확정 제공한다. 조건은 정상 감수분열의 기대값으로 판정하므로 비분리 표본의 운으로 부모 선택의 정오를 바꾸지 않는다. 4배체의 RRRr처럼 모든 정상 배우자에 R이 포함되는 경우도 계산한다. 실제 출하 모종의 배수성과 색도 별도로 검사한다. 새 조건은 `OrderInfo`와 기록의 선택 필드로만 확장해 기존 저장 형식을 유지했다.

단원 퀴즈는 `quizFor(..., mode)`로 나눴다. 성염색체 단원은 딸과 아들의 잎색을 함께 묻고, 염색체 단원의 시즌 6은 다루지 않은 당도 선발 대신 4배체 자가수분을 묻는다. 전체/빠른 연대기의 질문 선택지는 유지한다. `goalHint`는 어미/아비가 주는 X와 각 부모의 생식세포 조 수를 짚는다. 기존 xlinked, polyploid, triploid, nondisjunction 노트는 이 원리와 일치하며, 배수체 부모를 실제 교배하면 polyploid 노트도 열린다.

### 2. 카드와 넘김 단추 겹침의 원인 및 수정 근거

**후속 화면 검증으로 원인 기록을 정정한다.** Claude가 HEAD(bced04c)를 따로 실행한 결과, 768×1024에서 교배 단추가 보였고 카드와 넘김 단추도 겹치지 않았다. 겹침은 첫 학습 설계 수정에서 생긴 회귀다. 이전 소스 분석만으로 HEAD에도 문제가 있었다고 설명한 것은 부정확했다.

첫 학습 설계 수정은 예측 안내를 display:none에서 block으로 바꾸고 질문/선택지를 늘려 고정 영역의 높이를 늘렸다. 당시 온실은 글보다 작게 줄어들 수 있는 높이 구조였으며, 늘어난 예측 영역과 함께 회귀를 일으켰다. 아래 수정은 겹침을 없앴지만 행동 영역이 패널 스크롤 아래로 밀리는 새 문제가 확인되어, 뒤의 “교배 행동 영역 고정” 절에서 스크롤 구조를 다시 고쳤다.

수정한 높이와 흐름:

- 온실의 containment는 inline-size로 바꾸어 글의 세로 자연 높이를 계산에 포함한다. `flex: 1 0 auto`, `min-height: min-content`, 자연 높이의 grid 행으로 카드 영역을 글보다 작게 압축하지 않는다.
- 카드/몸체/면은 height:auto, 카드 상한은 해제한다. 그림만 `clamp(80px, 14dvh, 180px)`로 조절하고 설명과 유전자형 글은 축소하거나 자르지 않는다. 휴대전화의 기존 그림 높이 규칙은 유지한다.
- 넘김 영역은 카드 뒤의 정상 문서 흐름에서 최소 44px를 확보하며 축소하지 않는다. 선택 테두리를 위한 온실 내부 여백도 4px 확보한다.
- 세로 공간이 부족하면 `cross__right` 패널 전체가 `overflow-y: auto`로 스크롤된다. 카드, 넘김, 예측과 실행 영역을 각각의 자연 높이로 순서대로 읽을 수 있게 한다. 높이가 부족한 화면에서 한 화면 안에 모두 고정하는 방식은 유지하지 않는다.
- 휴대전화는 기존 2열/자연 문서 높이를 유지하고, 실행 단추는 필요하면 줄을 바꾼다. CSS `order`나 z-index로 내용을 덮어 겹침을 숨기지 않는다.

### 3. 부모 선택 → 예측 → 교배 실행

`CrossView`의 DOM을 `온실 → 넘김 → 선택한 부모 요약 → 예측/퍼넷 노트 → 오류 사유 → 실행 단추`로 바꿨다. 기존 부모 요약 바에서 자가수분/교배 실행 단추를 분리했다. 따라서 화면 읽기와 키보드 순서가 같다. 자가수분 선택/시작의 기존 동작, 예측 전 비활성, 부모 변경 시 예측 초기화, 정답 솎아내기 +1은 유지한다. 튜토리얼의 교배 단추 대상 선택자도 `.cross__actions .btn--play`로 맞췄다.

### 높이와 스크롤 흐름

## 2026-10-27 — 낮은 카드 영역에서 선택 근거 먼저 표시

사용자가 전달한 Claude 검증에서는 앞 절의 행동 영역 고정이 네 화면 크기 모두 통과했다. 넘김·선택 부모·예측·교배 단추가 스크롤 없이 보이고 겹침도 없었지만, 카드 목록 안에서는 큰 그림 때문에 이름·형질·유전자형이 가려졌다. 다음은 이번 수정 전의 측정값이다.

| 화면 | 카드 목록 내용/보이는 높이 | 가려진 정보 |

### 선택한 방법과 높이 근거

- 화면 폭이 768px 이상일 때만 `cross__catalog`를 이름 있는 size 컨테이너로 삼는다. 이 영역은 이미 남은 높이를 받는 `flex: 1 1 0; min-height: 0` 요소이므로, 카드 글의 높이를 억누르는 size containment를 카드 자체에 다시 적용하지 않는다. 행동 영역이 커지거나 줄어든 뒤 **실제로 남은 목록 높이**로 배치를 고른다.
- 목록 높이가 420px 이하이면 네 카드의 한 행을 유지하고 카드 내부를 grid로 바꾼다. **이름 전체 폭 → 48×48px 그림과 두 형질을 좌우로 → 당도·문양·초상·배지 → 유전자형 전체 폭** 순서다. 그림의 내부 padding도 0으로 하여 48px 상자 안에서 여백 때문에 그림이 더 작아지는 일을 피한다. 이름·형질·공개 유전자형의 기존 14px 글자 크기를 유지한다.
- 그림만 약 143px에서 48px로 줄여도 768px 화면의 190px 부족분을 모두 채우지 못한다. 따라서 그림과 형질의 높이를 합산하지 않는 배치, 리본/카드 안쪽의 작은 여백, 같은 행에 놓는 조작 안내와 부모 힌트를 함께 적용했다. 모든 이름·형질·유전자형 문구와 배지는 보존한다.
- 당도·문양·초상·편집 표시는 절대 위치를 해제해 독립 행에 둔다. 새로 위쪽에 놓인 이름이나 썸네일을 덮지 않는다. 초상과 편집 표시가 함께 있는 경우에도 서로 다른 행을 쓴다. 낮은 목록에서 카드 위에 떠 있던 중복 “부모” 표시는 숨기고, 선택 외곽선과 고정 행동 영역의 부모 요약은 유지한다.
